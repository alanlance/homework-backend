# 請求速率限制行為

此文件記錄需求釐清過程中已確認的行為；尚未代表功能已實作。

## 已確認行為

- 時間視窗從同一 API 金鑰的首次存取檢查請求起算，後續請求不延長視窗；到期後由下一次存取檢查請求開啟新視窗。
- 所有存取檢查嘗試都計入使用次數，包含超額被阻擋的請求；剩餘配額最低為 0。
- `/usage` 回傳使用次數、剩餘配額及視窗剩餘秒數（TTL）；查詢不增加計數，也不延長視窗。
- API 金鑰尚未建立限制規則時，`/check` 與 `/usage` 均回傳 HTTP `404`，不建立計數或時間視窗。
- 使用次數首次等於「請求上限 + 1」時，Producer 發送 `RateLimitExceededEvent` 至 RocketMQ；同一時間視窗內後續遭阻擋的請求不再發送。
- Consumer 將首次超額事件寫入 MySQL 稽核表，並以唯一的 `eventId` 防止重複消費造成重複資料。
- 已有規則的 `apiKey` 再次呼叫 `POST /limits` 時更新規則、回傳 HTTP `200`，並清除現有 Redis 視窗；首次建立回傳 HTTP `201`。
- 規則存在但沒有進行中的時間視窗時，`/usage` 回傳使用次數 `0`、完整剩餘配額與 TTL `0`，且不建立新視窗。
